## 问题描述

用户报告：锚点系统页面的 SAR 斜率数据没有联动，数据停留在 2026-01-17 19:00:00

截图显示：
- SAR 页面显示"空头1000多"（实际是序列号1270，表示连续下跌4.4天）
- 锚点系统页面的 SAR 数据没有更新到最新

## 问题根源

1. **数据流断裂**：
   - sar-jsonl-collector → 采集 SAR 数据到 `data/sar_jsonl/{symbol}.jsonl` ✅ 正常
   - latest_sar_slope.jsonl → 需要从上述文件合并生成 ❌ **没有自动生成**
   - 页面 API → 从 latest_sar_slope.jsonl 读取 ❌ 读取的是旧数据

2. **缺少更新脚本**：
   - 系统中没有自动更新 latest_sar_slope.jsonl 的守护进程
   - sar-slope-collector 写入数据库，但数据库表不存在
   - 导致 latest_sar_slope.jsonl 一直停留在旧数据

## 修复方案

### 1. 创建更新脚本 ✅

创建了 `update_latest_sar_slope.py`，功能：
- 从 data/sar_jsonl/*.jsonl 读取所有币种的最新数据
- 计算 SAR 斜率
- 合并生成 latest_sar_slope.jsonl

### 2. 添加守护进程 ✅

在 PM2 中添加 sar-slope-updater：
```bash
pm2 start source_code/update_latest_sar_slope.py \
  --name sar-slope-updater \
  --interpreter python3 \
  -- --daemon --interval 300
```

配置：
- 更新间隔: 300秒（5分钟）
- 自动运行: 是
- 日志: /home/user/.pm2/logs/sar-slope-updater-*.log

### 3. 验证数据流 ✅

完整的数据流：
```

  ↓
data/sar_jsonl/{symbol}.jsonl（27个币种）
  ↓
update_latest_sar_slope.py（每5分钟）
  ↓
data/sar_slope_jsonl/latest_sar_slope.jsonl
  ↓
/api/sar-slope/latest-jsonl
  ↓
锚点系统页面 + SAR斜率页面
```

## 关键数字说明

**1270 是什么？**
- 这是**序列号** (current_sequence)，不是数量
- 表示连续下跌的K线数量
- 1270 × 5分钟 = 6350分钟 ≈ 4.4天
- 这在持续下跌的市场中是正常现象

**序列号范围：**
- 1-10: 新转多空
- 10-50: 短期趋势
- 50-200: 中期趋势
- 200+: 长期趋势
- 1270: 超长期趋势（约4.4天）
