## 问题描述

用户反馈：锚点系统页面的 SAR 卡片显示 "偏多比 ≥ 33%" 是错误的，应该和 SAR 系统页面一样使用 "> 80%" 的标准。

## 根本原因

**两个页面使用了不同的数据指标**：

1. **SAR 系统页面** (`/sar-slope`):
   - 使用: **偏向比例 (bias_ratio)**
   - 计算方式: 统计最近一段时间内多头/空头的K线占比
   - 数据来源: `/api/sar-slope/current-cycle/{symbol}`
   - 筛选条件: 偏向比例 > 80%

2. **锚点系统页面** (`/anchor-system-real`) - 修复前:
   - 使用: **斜率值 (slope_value)**
   - 计算方式: SAR 值的变化趋势（-1 到 1）
   - 数据来源: `/api/sar-slope/latest-jsonl`
   - 筛选条件: 斜率值 ≥ 0.33（33%）

**这是两个不同的指标！**

## 数据对比

### 指标说明

**斜率值 (slope_value)**:
- 范围: -1 到 1
- 含义: SAR 点位的变化趋势
- 示例: 0.6667 表示 SAR 强势上升

**偏向比例 (bias_ratio)**:
- 范围: 0% 到 100%
- 含义: 一段时间内多头/空头K线的占比
- 示例: 85.5% 表示 85.5% 的时间是多头

## 技术细节

### API 端点对比

**1. `/api/sar-slope/latest-jsonl`**
- 返回: 所有币种的最新快照
- 数据: slope_value, sar_position, datetime
- 用途: 快速获取所有币种状态
- 特点: 静态快照，从JSONL文件读取

**2. `/api/sar-slope/current-cycle/{symbol}`**
- 返回: 单个币种的当前周期统计
- 数据: bullish_ratio, bearish_ratio, bias_statistics
- 用途: 详细的偏向统计分析
- 特点: 动态计算，统计一段时间的数据

### 性能影响

**修改前**:
- 1 次 API 调用（latest-jsonl）
- 响应时间: ~100ms
- 数据量: 27 个币种一次性获取

**修改后**:
- 27 次 API 调用（每个币种一次）
- 响应时间: ~2-3s（并发请求）
- 数据量: 每个币种单独请求

**优化**: 使用 `Promise.all()` 并发请求，减少总耗时
