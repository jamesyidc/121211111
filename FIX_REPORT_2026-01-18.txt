## 问题总结

### 1. ❌ 27币数据 23:00 和 23:30 错误
**问题描述**: 
- 2026-01-17 的 23:00 和 23:30 两个时间点的数据异常
- 23:00: 显示 0.19%（应该是 83%左右）
- 23:30: 显示 0.07%（应该是 83%左右）
- 22:30: 82.39% ✅ 正常
- 00:00: -0.58% ✅ 正常（跨天重置基准）

**根本原因**:
coin_price_tracker.py 的 `fetch_base_prices()` 函数在检测到新一天时，
会使用**当前实时价格**作为基准，而不是使用00:00的历史价格。

这导致在 23:00 和 23:30 时刻：
1. 检测到日期变化（虽然还在1月17日）
2. 调用 fetch_base_prices() 获取"基准价格"
3. 但获取到的是 23:00/23:30 时刻的实时价格
4. 计算涨跌幅时，(当前价 - 基准价)/基准价 ≈ 0%

### 2. ❌ 爆仓数据不更新
**问题描述**:
- 1小时爆仓金额一直显示 124.81万（从00:18到00:37不变）
- 目标网站 https://history.btc126.com/baocang/ 改版为Vue.js渲染
- 原有采集方式失效

### 3. ❓ 跨日期数据自动添加
**检查结果**: 系统已正常处理跨日期数据
- 数据范围: 2026-01-03 ~ 2026-01-18 ✅
- 自动更新器每5分钟运行一次 ✅
- SR快照采集器每分钟运行一次 ✅

**修复方法**:

- 备份文件: coin_prices_30min.jsonl.backup.before_fix_2330

#### 步骤2: 修复采集脚本
**修改文件**: source_code/coin_price_tracker.py
**修改内容**:
1. 增强 `fetch_base_prices()` 函数：
   - 新增参数 `force_realtime`
   - 在非00:00-00:30时段，优先从历史记录读取基准价格
   - 新增 `load_base_prices_from_history()` 方法

2. 核心逻辑改进：
```python
# 修复前：
def fetch_base_prices(self):
    # 直接获取实时价格作为基准 ❌
    price = self.fetch_okx_price(symbol)

# 修复后：
def fetch_base_prices(self, force_realtime=False):
    is_early_morning = now.hour == 0 and now.minute < 30
    
    # 非凌晨时段，从历史记录读取 ✅
    if not force_realtime and not is_early_morning:
        base_prices = self.load_base_prices_from_history(today_start)
        if base_prices:
            return base_prices
    
    # 凌晨时段才获取实时价格 ✅
    price = self.fetch_okx_price(symbol)
```
