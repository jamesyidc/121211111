### ✅ 冷却期机制

**目的**: 避免同一极值事件的重复触发

**实现方式**:
1. 每次触发记录触发时间到 `trigger_cooldown.jsonl`
2. 检查时计算时间差，4小时内不再触发
3. 不同类型独立计算
4. 日志显示剩余冷却时间

**冷却期文件示例**:
```json
{
  "2h_peak": 1737213123,
  "27coins_high": 1737209523,
  "1h_liquidation_high": 1737206923
}
```

## 📊 API接口

### 1. 获取快照列表
```
GET /api/extreme-tracking/snapshots

参数:
  - limit (int): 返回数量限制
  - status (string): active/completed 过滤状态

示例:
curl "http://localhost:5000/api/extreme-tracking/snapshots?limit=10&status=active"
```

### 2. 获取单个快照详情
```
GET /api/extreme-tracking/snapshot/<snapshot_id>

示例:
curl "http://localhost:5000/api/extreme-tracking/snapshot/EXT_1737213123"
```

### 3. 获取统计信息
```
GET /api/extreme-tracking/stats

返回:
  - total_snapshots: 总快照数
  - active_snapshots: 活跃快照数
  - completed_snapshots: 完成快照数
  - trigger_types: 各类型触发次数
  - average_price_changes: 平均价格变化

示例:
curl "http://localhost:5000/api/extreme-tracking/stats"
```

## 🎯 工作流程

```
1. 每10分钟检查一次
   ↓
2. 获取逃顶信号数据
   ↓
3. 获取27币涨跌数据
   ↓
4. 获取1小时爆仓数据
   ↓
5. 检查5种触发条件
   ↓
6. 检查冷却期状态
   ↓
7. 如果触发且不在冷却期
   ├─ 创建快照
   ├─ 保存到JSONL
   ├─ 更新冷却期
   └─ 记录日志
   ↓
8. 检查活跃快照
   ↓
9. 更新追踪数据
   ├─ 1小时后
   ├─ 3小时后
   ├─ 6小时后
   ├─ 12小时后
   └─ 24小时后
   ↓
10. 标记为completed
    ↓
11. 等待下次检查
```
