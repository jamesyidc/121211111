✅ 2. Telegram告警监控 (liquidation_alert_monitor.py)

新增功能:
- 持续监控1小时爆仓金额
- 超过3000万美元自动发送Telegram告警
- 30分钟冷却机制，避免频繁告警
- 记录告警历史

主要特性:
1) 数据监控
   - 每1分钟检查一次最新数据
   - 从 panic_wash_index 获取实时数据
   - 支持自动重连和错误恢复

2) 告警机制
   - 阈值: 3000万美元（可配置）
   - 冷却时间: 30分钟（可配置）
   - 消息格式: Markdown格式，包含详细信息

3) 告警消息内容
   ```
   🚨 爆仓金额告警 🚨
   
   💥 1小时爆仓金额: XXX 万美元
   ⚠️ 告警阈值: 3000 万美元
   📈 超出比例: XX%
   
   ⏰ 数据时间: YYYY-MM-DD HH:MM:SS
   📍 告警时间: YYYY-MM-DD HH:MM:SS
   
   🔗 查看详情: [链接]
   ```

4) 告警记录
   - 文件: data/liquidation_alert_records.json
   - 保存最近100条告警记录
   - 记录告警时间、金额、阈值等信息

5) Telegram配置
   - 配置文件: configs/telegram_config.json
   - 需要配置: bot_token, chat_id
   - 支持多个chat_id（数组格式）

九、故障排查
================================================================

❌ 问题1: 图表不显示24小时最大值标记

解决方案:
1. 清除浏览器缓存
2. 强制刷新页面 (Ctrl+F5)
3. 检查浏览器控制台是否有JavaScript错误

❌ 问题2: Telegram通知未发送

检查清单:
1. 检查telegram_config.json是否存在且配置正确
2. 检查bot_token和chat_id是否有效
3. 检查网络连接是否正常
4. 查看日志: pm2 logs liquidation-alert-monitor

解决方案:
```bash
# 测试Telegram配置
cd /home/user/webapp
python3 << 'EOF'
import json
config = json.load(open('configs/telegram_config.json'))
print("Bot Token:", config.get('bot_token')[:20] + "...")
print("Chat ID:", config.get('chat_id'))
EOF
```

❌ 问题3: 监控进程频繁重启

检查清单:
1. 查看错误日志: tail -100 logs/liquidation_alert_error.log
2. 检查内存使用: pm2 describe liquidation-alert-monitor
3. 检查数据文件是否损坏

解决方案:
```bash
# 重启进程
pm2 restart liquidation-alert-monitor

# 查看详细信息
pm2 describe liquidation-alert-monitor
```
